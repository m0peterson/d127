# d127: цитата дня

Тапаешь кнопку, одновременно бросаются страница (d127) и строка (d3), по результату из сборника достаётся цитата дня в духе Стэтхема. Мобильное веб-приложение: работает на любом устройстве, ставится на домашний экран, открывается без сети.

Есть второй режим: LLM сочиняет новую цитату на каждый бросок. Модель выбирается в шестерёнке. Можно пользоваться ключом владельца сайта из настроек Netlify или указать свой ключ OpenRouter.

## Как это устроено

```
браузер  --{ d127, d3, model, apiKey? }-->  /api/quote (Netlify Function)  -->  OpenRouter
                                             apiKey или серверный LLM_API_KEY
                                             выбранная модель и резервные модели
```

- Серверный ключ `LLM_API_KEY` остаётся в переменных окружения Netlify и не отправляется в браузер. Свой ключ посетителя хранится в `localStorage` его браузера и передаётся функции вместе с запросом по HTTPS. Очистка поля удаляет сохранённый личный ключ и возвращает использование серверного.
- Браузер присылает числа, выпавшие на кубиках, выбранную модель и необязательный личный ключ. Можно добавить список своих цитат из шестерёнки (до 300 строк по 300 символов, лишнее функция отсекает). Сервер разрешает только три модели из списка ниже и сам задаёт промпт, рассуждения и лимит токенов. Если своего списка нет, примеры берутся из сборника `quotes.txt`.
- Функция не чат: задание модели фиксировано, ответ ограничен `MAX_TOKENS`, своё попадает в промпт только как список примеров. Но это ослабленная защита: кто-то может подобрать «примеры» так, чтобы подтолкнуть ответ. Потолок трат при этом тот же: лимит запросов и лимит денег на ключе.
- Сборник `quotes.txt` лежит внутри пакета функции: так его кладёт строка `included_files` в `netlify.toml`. Функции не нужно скачивать его с собственного сайта, поэтому она работает и на закрытых превью (пароль, вход в Netlify), куда её же запрос не пустили бы.

### Модель и свой ключ без деплоя

Открой шестерёнку и выбери источник **LLM**. В настройках доступны три модели OpenRouter:

| Модель | Рассуждения | Резервные модели при ошибке |
| --- | --- | --- |
| `meta/muse-spark-1.3-contributor` (по умолчанию) | `high`, если поддерживается | `xiaomi/mimo-v2.6-pro` → `anthropic/claude-haiku-5.5` |
| `xiaomi/mimo-v2.6-pro` | `high`, если поддерживается | `anthropic/claude-haiku-5.5` |
| `anthropic/claude-haiku-5.5` | `xhigh`, если поддерживается | Нет |

Функция учитывает сведения OpenRouter о поддержке рассуждений: использует запрошенный уровень, если он доступен, иначе самый высокий доступный. Если провайдер отклоняет `xhigh`, запрос повторяется с `high`; если уровень или параметр рассуждений не поддерживается, функция повторяет запрос без него. Если модель не отвечает, функция переходит к следующей резервной. Когда вся цепочка не сработала, приложение показывает цитату из сборника. Доступность указанных id и уровней зависит от OpenRouter и провайдера модели.

Поле **Свой ключ OpenRouter** необязательное и скрывает введённые символы. Пока оно пустое, запрос использует `LLM_API_KEY` сайта. При заполнении все попытки идут через OpenRouter с твоим ключом; ошибка личного ключа не переключает запрос на ключ сайта. Выбор модели и ключ сохраняются только в этом браузере, изменения работают сразу. Личный ключ можно посмотреть через инструменты браузера, поэтому вводи его только на доверенном сайте и устройстве. Не помещай ключ в репозиторий.

### Что защищает твой ключ от злоупотреблений

| Мера | От чего защищает | Чего не закрывает |
| --- | --- | --- |
| Серверный ключ только на сервере | Ключ сайта не достать из кода страницы, из DevTools и из localStorage | Личный ключ хранится в браузере того, кто его ввёл |
| Три разрешённые модели, промпт и размер ответа задаёт сервер | Нельзя выбрать произвольную дорогую модель или увеличить лимит ответа. Свой текст попадает в промпт только как примеры, не длиннее 300 символов на строку | Не мешает «подсказать» модели нужный тон через примеры |
| Лимит 10 запросов в минуту с одного IP (Netlify) | Один человек или скрипт не может гонять запросы потоком | Много IP сразу (ботнет). Сотни человек за одним IP (офис, оператор) делят один лимит |
| Отдельный ключ с лимитом денег у провайдера | **Абсолютный потолок трат**, что бы ни случилось | Ничего, это последняя линия. Настрой её обязательно |
| Быстрая отмена: отозвать ключ у провайдера | Остановка за секунды | |

Честно про масштаб. Запрос включает инструкцию и 30 примеров. Короткая цитата не означает короткий оплачиваемый ответ: модель может потратить токены на рассуждения, а при сбое запросить резервные модели. `MAX_TOKENS` ограничивает каждую попытку, а не общую стоимость броска. Лимит 10 в минуту позволяет до 14 400 бросков в сутки с одного IP. Проверяй актуальные цены всех трёх моделей и расходы в OpenRouter Activity, а абсолютный потолок задавай через Credit limit ключа. Это относится и к серверному, и к личному ключу.

Если рассчитываешь на большую нагрузку, лимит в коде тоже можно затянуть (см. «Настройка»).

## Деплой: пошагово

Понадобятся: аккаунт на GitHub, аккаунт на [Netlify](https://app.netlify.com) (бесплатного хватает) и аккаунт у одного LLM-провайдера. Названия пунктов меню у сервисов иногда меняются, суть остаётся: ищи разделы про ключи, лимиты и переменные окружения.

### Шаг 1. Получи ключ у провайдера

Для нового интерфейса нужен **API-ключ OpenRouter**. Модели уже перечислены в приложении, задавать их на Netlify не нужно.

**Вариант A: OpenRouter** (платишь за токены, можно жёстко ограничить сумму)

1. Зайди на [openrouter.ai](https://openrouter.ai), войди, пополни баланс на небольшую сумму: для этого сайта хватит нескольких долларов.
2. Открой [openrouter.ai/settings/keys](https://openrouter.ai/settings/keys), нажми **Create Key**.
3. Имя: `d127`. В поле **Credit limit** поставь потолок, например `5` (доллары). Это и есть твой предохранитель: когда ключ потратит эту сумму, OpenRouter начнёт отклонять запросы, а приложение покажет цитату из сборника.
4. Нажми создать и **сразу скопируй ключ**, он выглядит как `sk-or-v1-...`. Второй раз его не покажут. Он пойдёт в `LLM_API_KEY`.
5. Проверь доступность моделей и их цены на [openrouter.ai/models](https://openrouter.ai/models). Ключ можно положить в `LLM_API_KEY` сайта или ввести в поле личного ключа в приложении.

**Совместимость: OpenCode Go** (подписка, прежние API-клиенты)

Этот путь оставлен для запросов без `model` и `apiKey` с `LLM_PROVIDER=opencodego`. Новый интерфейс передаёт выбранную модель и работает через OpenRouter.

1. Зайди на [opencode.ai](https://opencode.ai), оформи подписку Go и открой консоль.
2. Создай API-ключ в разделе с ключами и скопируй его. Он пойдёт в `LLM_API_KEY`.
3. Возьми id модели из списка моделей Go в консоли или документации. Приставку `opencode-go/` можно оставить, она отрежется сама. Id пойдёт в `LLM_MODEL`.
4. Учти: потолок трат тут задаёт сама подписка. Проверь в консоли, что при исчерпании лимита ничего не докупается автоматически. Если докупается, лучше вариант A.

**Время и рассуждения.** Модели запускаются с `high` или `xhigh`, когда провайдер это поддерживает. У функции общий бюджет обращений к OpenRouter 25 секунд, включая получение сведений о моделях (до 1 секунды). Оставшееся время делится между оставшимися моделями: для цепочки из трёх моделей первая получает около 8 секунд, при выборе MiMo первая получает около 12 секунд, а Haiku без резервных моделей получает весь остаток. Быстрый сбой оставляет больше времени следующим моделям. Исходный запрос и повторы для совместимости рассуждений используют общую долю времени своей модели. Проверь, что лимит синхронной функции твоего тарифа Netlify позволяет этот бюджет с запасом на остальную обработку. При медленной модели приложение использует резервную модель или сборник.

### Шаг 2. Создай сайт на Netlify

**Путь 1. Кнопка (сайта ещё нет).**

[![Deploy to Netlify](https://www.netlify.com/img/deploy/button.svg)](https://app.netlify.com/start/deploy?repository=https://github.com/m0peterson/d127#LLM_PROVIDER,LLM_API_KEY)

Нажми, войди в Netlify, подтверди доступ к GitHub. Netlify скопирует репозиторий в твой аккаунт и опубликует сайт. Кнопка должна спросить две переменные из следующего шага: впиши их прямо тут. Если не спросила, добавь их вручную по шагу 3.

**Путь 2. Вручную.**

1. В Netlify: **Add new project** → **Import an existing project** → GitHub → выбери репозиторий.
2. Поля сборки оставь пустыми. Build command не нужен, папка публикации `public` уже прописана в `netlify.toml`.
3. Нажми **Deploy**. Сборник работает сразу. Для LLM добавь серверный ключ по шагу 3 или введи личный ключ OpenRouter в приложении.

**Путь 3. Сайт уже задеплоен из репозитория.** Влей эту ветку в ту ветку, которую Netlify выкатывает (обычно `main`). Если сайт крутится на копии репозитория в твоём GitHub (так работает кнопка), изменения нужно перенести в эту копию. Netlify перевыложит сайт сам.

### Шаг 3. Впиши переменные окружения

Это главный шаг: тут ключ ложится на сервер. Посетители пользуются им через функцию, но увидеть его не могут.

1. В Netlify открой свой сайт → **Site configuration** → **Environment variables**.
2. Нажми **Add a variable** → **Add a single variable** и создай переменные:

| Ключ (Key) | Значение (Value) | Пример |
| --- | --- | --- |
| `LLM_PROVIDER` | `openrouter` для нового интерфейса | `openrouter` |
| `LLM_API_KEY` | ключ провайдера из шага 1 | `sk-or-v1-...` |

3. Для `LLM_API_KEY` включи галочку **Contains secret values** (значение будет скрыто после сохранения). В **Scopes** должна стоять область **Functions**: оставь значение по умолчанию, если оно её включает. **Deploy contexts** оставь «All».
4. Сохрани.

Если `LLM_PROVIDER` не задать, будет `openrouter`. `LLM_MODEL` для OpenRouter не используется: выбор делается в приложении, по умолчанию стоит Muse Spark. `LLM_MODEL` нужен только для совместимости с OpenCode Go, описанной в шаге 1. Если все посетители вводят личные ключи, серверный `LLM_API_KEY` можно не задавать.

### Шаг 4. Передеплой (обязательно)

Netlify применяет новые значения переменных только к новым выкаткам, поэтому после добавления или изменения любой из них сайт нужно выложить заново: **Deploys** → **Trigger deploy** → **Deploy site**. Без этого шага приложение отвечает, что генерация не настроена.

Кнопка пересобирает то, что лежит в репозитории, к которому привязан сайт. Если код с функцией туда ещё не влит (или сайт привязан к другой копии репозитория, или его выкладывали вручную), переменные появятся, а функции в деплое не будет вовсе. Проверь: открой опубликованный деплой в **Deploys**, в нём должен быть блок **Functions** с функцией `quote`. Если его нет, приложение пишет «на этом хосте нет серверной функции».

### Шаг 5. Проверь

1. Открой сайт, шестерёнка → источник **LLM** → закрой → брось кубики. Под цитатой должно появиться «сочинила LLM в духе Стэтхема».
2. Или без интерфейса, из терминала:
   ```sh
   curl -X POST https://ТВОЙ-САЙТ.netlify.app/api/quote \
     -H 'Content-Type: application/json' \
     -d '{"d127":5,"d3":2}'
   ```
   Ответ `{"text":"..."}` значит, что всё работает.
3. Проверь, что лимит сработает, и не потрать при этом токены. Отправь 15 запросов подряд с заведомо неверным телом: такие запросы отбивает сама функция, к провайдеру они не идут, а лимитер Netlify считает их наравне с обычными.
   ```sh
   for i in $(seq 15); do curl -s -o /dev/null -w "%{http_code} " -X POST https://ТВОЙ-САЙТ.netlify.app/api/quote -H 'Content-Type: application/json' -d '{}'; done; echo
   ```
   Сначала пойдут `400`, ближе к концу серии должны появиться `429`.
4. Проверь потолок у провайдера: у OpenRouter в [Activity](https://openrouter.ai/activity) должны появляться запросы, а у ключа в списке ключей стоять твой Credit limit.

Проверка проводки без трат: временно поставь `LLM_PROVIDER=mock` (ключ и модель тогда не нужны), очисти личный ключ в приложении и передеплой. Функция вернёт случайную цитату из сборника и ничего не потратит. Личный ключ включает OpenRouter даже в mock-окружении. После проверки верни настоящий провайдер и снова передеплой.

### Если что-то не работает

Сначала смотри логи функции: **Logs** → **Functions** → `quote`. Там причина, которую посетителю не показывают.

| Что видно | Причина и что делать |
| --- | --- |
| «генерация не настроена на сервере» (503) | Нет переменной или после её добавления не было передеплоя (шаг 4). В логах написаны все недостающие переменные сразу |
| «сервер не смог загрузить сборник цитат» (503) | Функция не нашла `public/data/quotes.txt` у себя в пакете и не смогла скачать его с сайта. Проверь, что в `netlify.toml` есть `included_files` с этим файлом, и передеплой. Подробности в логе: там обе причины |
| «сервер сейчас недоступен» (503) | Ответила не функция, а сама платформа: например, сайт приостановлен из-за лимитов тарифа. Смотри кабинет Netlify |
| «модель не ответила» (502), в логах `HTTP 401` | Ключ неверный или отозван. Проверь, что вставил ключ целиком и без пробелов |
| 502, в логах `HTTP 402` или про кредиты | Кончился баланс или сработал Credit limit. Пополни или подними лимит |
| В логах `HTTP 403` | Провайдер ограничил доступ к модели; функция пробует следующую резервную. Если цепочка не сработала, проверь ограничения ключа или выбери другую модель |
| 502, в логах `HTTP 404` или про модель | Модель недоступна у провайдера. Проверь её наличие в OpenRouter и попробуй другую модель в шестерёнке |
| 502, «пустой ответ модели» | Все доступные попытки не вернули текст, например рассуждения исчерпали лимит токенов. Попробуй другую модель в шестерёнке |
| 502, «нет ответа за 25 секунд» или ответ 504 | Исчерпан общий бюджет ожидания или лимит функции Netlify. Выбери другую модель и проверь лимит времени в настройках Netlify |
| «слишком много запросов» (429) | Сработал лимит 10 в минуту с твоего IP. Подожди минуту |
| «на этом хосте нет серверной функции» (404) | Сайт открыт без Netlify, например через `python3 -m http.server`. Функция есть только на Netlify и в `netlify dev` |

Во всех этих случаях приложение не ломается, а показывает цитату из сборника.

## Как менять настройки потом

- **Сменить модель или личный ключ.** Открой шестерёнку в приложении. Изменение работает сразу, деплой не нужен. Пустое поле личного ключа возвращает использование серверного.
- **Сменить серверный ключ.** Site configuration → Environment variables → `LLM_API_KEY` → измени → сохрани → передеплой (шаг 4).
- **Заменить ключ, если он утёк или просто по гигиене.** Создай новый ключ у провайдера с тем же лимитом, вставь в `LLM_API_KEY`, передеплой, только потом удали старый.
- **Срочно выключить использование серверного ключа.** Отзови или удали ключ в кабинете провайдера. Запросы с ним начнут падать, приложение будет показывать сборник. Потом можно удалить `LLM_API_KEY` и передеплоить. Посетители с личными ключами продолжат пользоваться LLM.

## Настройка

Всё в коде, правится прямо на GitHub, после коммита Netlify перевыкатывает сайт.

- **Лимит запросов**: `config.rateLimit` в [`netlify/functions/quote.mjs`](netlify/functions/quote.mjs). `windowLimit` это число запросов, `windowSize` это окно в секундах. Сейчас 10 в 60. Хочешь строже, поставь, например, 5.
- **Текст промпта и тон**: `SYSTEM_PROMPT` в [`netlify/lib/llm.mjs`](netlify/lib/llm.mjs). По умолчанию модель не использует мат, если его нет в примерах.
- **Потолок токенов каждой попытки**: `MAX_TOKENS` там же (сейчас 8192, с запасом на рассуждения). Меньше значение снижает максимальную трату одной попытки, но может не оставить токенов для самой цитаты. Резервные попытки тоже могут расходовать токены.
- **Сколько примеров уходит в модель**: `EXAMPLES_PER_REQUEST` там же (сейчас 30 случайных цитат из сборника).
- **Какой режим включён у новых посетителей**: по умолчанию LLM, а если модель не ответила, показывается цитата из сборника. Токены тратятся с первого броска каждого нового посетителя, потолок задают лимит запросов и лимит денег на ключе. Хочешь наоборот, поставь `source: 'collection'` в `DEFAULT_SETTINGS` в [`public/js/settings.js`](public/js/settings.js).

## Как работает бросок

Два кубика бросаются за один тап, случайность берётся из `crypto.getRandomValues` без перекоса.

`слот = (страница - 1) * 3 + строка`

Получается ровно 127 × 3 = 381 слот, и в сборнике 381 цитата: у каждого исхода своя.

В режиме LLM цитата из слота становится темой, а остальные цитаты сборника служат примерами стиля. Модель пишет новую цитату в том же духе. Задача у неё одна: тупо, смешно, кринжово и с серьёзным лицом.

## Свои примеры для LLM без деплоя

В шестерёнке есть поле «Свои примеры для LLM»: вставь цитаты по одной на строку. Нумерация, маркеры списка, пустые строки и строки с `#` отбрасываются. Список хранится в браузере и уходит на сервер вместе с броском, поэтому деплой не нужен, правка работает сразу. Пока поле пустое, примеры берутся из сборника. Тема (якорь) в любом случае берётся из слота броска.

Список личный: он есть только в том браузере, где его ввели. Общие для всех посетителей цитаты и сборник по-прежнему меняются через `quotes.txt` и деплой.

## Свои цитаты

Сборник лежит в [`public/data/quotes.txt`](public/data/quotes.txt): одна цитата на строку, порядковый номер строки и есть слот. Строки с `#` и пустые строки игнорируются. Если цитат меньше 381, пустые слоты берут цитату по кругу.

Чтобы заменить цитату, отредактируй строку прямо на GitHub и закоммить. Netlify перевыложит сайт. Старые посетители увидят новую версию со второго открытия (кэш обновляется в фоне).

Сборник работает и как база примеров для модели, так что чем лучше цитаты в нём, тем лучше LLM подражает стилю.

## Локальный запуск

Только сборник, без LLM:

```sh
python3 -m http.server -d public 8080
```

Открой `http://localhost:8080`. Service worker работает только по HTTPS или на localhost. В режиме LLM тут будет ошибка про отсутствие серверной функции, это нормально.

С LLM (запускает и сайт, и функцию, как на Netlify):

```sh
cp .env.example .env     # для OpenRouter впиши LLM_PROVIDER и LLM_API_KEY; без трат оставь mock
npx netlify-cli dev
```

Открой адрес, который напечатает команда (обычно `http://localhost:8888`). Файл `.env` в git не попадает.

Тесты серверной функции (проверено на Node 22):

```sh
npm test
```

```
netlify/
  functions/quote.mjs       POST /api/quote: проверка запроса, лимит, вызов провайдера
  lib/llm.mjs               промпт, OpenRouter, OpenCode Go, мок
  lib/collection.mjs        сборник для функции: файл из пакета, запасной путь через сайт
public/
  index.html
  css/style.css
  js/app.js                 интерфейс и бросок
  js/dice.js                d127 и d3
  js/quotes.js              загрузка сборника и поиск по слоту
  js/settings.js            localStorage: источник, модель, личный ключ и последний бросок
  js/models.js              разрешённые модели OpenRouter и порядок резервных моделей
  js/llm.js                 запрос к /api/quote
  data/quotes.txt           381 цитата
  sw.js                     офлайн-кэш
test/quote.test.mjs         тесты функции
```
